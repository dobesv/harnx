Steering messages into a running A2A conversation now join its live turn and answer on the same task instead of failing with the busy error. A `SendMessage` or `SendStreamingMessage` for a context whose task is still running is delivered to that task's turn as new user input (injected at the next tool-round seam, or answered in a continuation round under the same invocation when the turn has no seam), returns the same task id, and streams on that task. Retries with the same `messageId` dedupe to the same task while it is live, without double delivery (a crash between appending the row and recording its mapping, followed by the task settling before the retry, is the documented at-least-once crash window and can re-answer on a new task); changed parts under the same id still fail the fingerprint check. Parked `INPUT_REQUIRED` tasks keep their dedicated reply path and busy error, and a fresh message after the previous task drained its steered continuation rounds no longer wedges the context. A steered continuation round that needs human approval parks the task as `INPUT_REQUIRED` on the same task, and approving it now resumes the drain: replies to such a challenge wake the owning worker, and an in-flight continuation round resumes with the steered row as its initiating user message.
