`harnx-mcp-remote` (stdio proxy) can now authenticate to an upstream MCP server with an OAuth 2.0 `client_credentials` grant: pass `--oauth-token-url` (or `MCP_REMOTE_OAUTH_TOKEN_URL`) with `--oauth-client-id` and `--oauth-client-secret-file`, and the proxy validates endpoints lazily on first connect, exchanges the grant with a 30-second total deadline on the first authenticated request, caches tokens in memory only, refreshes inside the 60-second pre-expiry window (or only on an identifiable HTTP `401` when `expires_in` is omitted), and replays `POST`/SSE `GET` at most once on an identifiable `401` (failing closed on statusless malformed challenges). The mode is opt-in and conflict-checked (`--bearer-token`, custom `Authorization` headers and native mode are rejected), requires `http`/`https` with HTTPS or loopback on both endpoints unless `--insecure` (which waives endpoint HTTPS policy only, not TLS certificate verification), refuses URLs with embedded credentials, ignores system proxies and redirects, and shares the configured TLS identity/CA between the grant and MCP clients. Upstream failure text on failed tool results (`is_error: true`), JSON-RPC errors and connect/recovery failures is replaced with static diagnostics (successful tool output passes through unchanged), token errors return only static text, known HTTP status and allowlisted OAuth codes, stderr is restricted to app-owned targets and OTLP excludes `rmcp`, `reqwest`, `hyper` and `hyper_util` (exact targets and `::` descendants) in this mode, and plain proxy and native mode defaults are unchanged.
