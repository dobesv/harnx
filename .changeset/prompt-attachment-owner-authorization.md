Authorize `session/prompt` attachment refs against their source session owner when access rules are enabled.
With access rules on, a `cid:media` attachment ref supplied to the protected JSON-RPC prompt ingress is now checked against the session that uploaded it before the prompt is admitted: the caller must have the same access to that source session that the session routes require (matching owner, alias expansion, or admin scope on the source agent, normalized for the destination cluster). Previously any holder of a ref could attach private media to a prompt in a session they control, letting the destination model read content another user uploaded. Unauthorized or unattributed sources now fail closed with a generic `-32005` "attachment not found" JSON-RPC error before any log append, turn activation, or blob lookup; malformed refs keep their validation rejection. Same-session refs, a caller's own cross-session refs, admin callers, and rules-off bearer-CID behavior are unchanged.
Authorization now opens the session metadata bucket read-only once per prompt — no provisioning `ensure`, one broker connection per request instead of one per source, leader-backed reads preserved, and none at all for prompts without `cid:media` refs — and a prompt carrying more than 32 `cid:media` refs is rejected with `-32602` (HTTP 400) before any broker work. When the source session's metadata cannot be read because the broker is unavailable, the prompt fails closed with `-32003` (HTTP 503) "session metadata unavailable" instead of the generic 404, and the failure is logged server-side at `warn`, so an outage is no longer indistinguishable from a denial. Any other read failure — an absent record, an undecodable one — keeps the generic 404 denial.
