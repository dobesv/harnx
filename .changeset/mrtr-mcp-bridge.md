MCP tools join the same input_required flow as native tools. Bridged MCP servers that speak the 2026-07-28 protocol revision (MRTR, SEP-2322) can suspend a `tools/call` with `inputRequests` and `requestState`; the bridge maps the single elicitation request onto the native challenge path (confirm, or the documented A2UI subset: string properties become text fields, enums become choice pickers), and re-calls with `inputResponses` plus the echoed `requestState` beside the unchanged arguments. Sampling, roots, URL elicitation, multi-request and malformed results fail with a clear error, never a silent success. Harnx tool servers exported over MCP return a real `input_required` response instead of the compatibility error, and answers arrive through `ToolInvocationContext` unchanged. The MRTR capability is server-level: tools of a server that negotiated the revision are stamped `harnx:input_required`; older peers keep working over the legacy `initialize` handshake. A looping tool is cut off after 10 challenge rounds with a visible error result.
