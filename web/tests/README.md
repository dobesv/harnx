# End-to-End Tests

This directory contains Playwright e2e tests for the web UI.

## Running Tests

```bash
cd web
pnpm test:e2e
```

Playwright automatically starts a dev server on port 5174 with MSW enabled (see below).
No manual server startup required.

## First-Time Setup

Install Playwright's Chromium browser:

```bash
cd web
pnpm exec playwright install chromium
```

On first run in CI or fresh environments, `--with-deps` installs system dependencies too:

```bash
pnpm exec playwright install --with-deps chromium
```

## Updating Screenshots

When UI changes are intentional, update screenshots:

```bash
pnpm test:e2e:update
```

This runs Playwright with `--update-snapshots`. Review the changed PNGs in git diff
before committing. Screenshots are committed for human review, not as a strict pixel-perfect gate.

### Avoid committing locally-generated baselines

Visual baselines are committed as `*-linux.png` files and regenerated by the
required `Playwright E2E Tests` CI workflow on `ubuntu-latest` with
`pnpm exec playwright install --with-deps chromium` (see
`.github/workflows/web-e2e.yml` and `.mergify.yml`).

Local installs without root access can only run `playwright install chromium`
(without `--with-deps`), which pulls the OS fallback build and renders fonts
slightly differently from CI. This baseline drift (~0.004–0.01 pixel-ratio on
unaffected screens) can exceed the actual layout change.

For small CSS layout changes that pass `pnpm test:e2e` locally against
committed baselines, **do not run `pnpm test:e2e:update` locally**. The
2% `maxDiffPixelRatio` gate (see `playwright.config.ts`) guarantees CI passes
with equal-or-greater margin: CI diff = layout delta only; local diff = layout
delta + environment drift.

If a change legitimately exceeds the gate, prefer having CI regenerate
baselines (download artifacts from a failed run, commit the updated PNGs) or
use an ephemeral workflow dispatch.

### Behavioral assertions over pixel matches

A screenshot test alone may not detect small layout changes due to the 2%
tolerance. For layout changes that must not regress, add a behavioral
computed-style assertion. See `web/tests/e2e/composer.spec.ts` for an example
that checks `borderTopWidth === 0` and padding sides `> 0`.

## MSW (Mock Service Worker)

E2e tests use MSW to mock the backend API:

- **E2e mode**: `VITE_ENABLE_MSW=true` enables MSW. Playwright's config starts the dev server with this flag.
- **Normal dev/build**: MSW is OFF. Running `pnpm dev` or `pnpm build` without the flag uses the real backend.

## Scenario Selection

Tests drive different MSW scenarios via the `?scenario=<name>` URL param:

| Scenario | Description |
|----------|-------------|
| `happy` | Normal success responses (default) |
| `agentsFail` | `/v1/agents` returns 500 |
| `sessionsFail` | `/v1/agents/:agent/sessions` returns 404 |
| `sendFail` | RPC POST returns 500 |

See `web/src/mocks/handlers.ts` for handler implementations.

## Dev Server Port

Playwright runs the dev server on port **5174** (configured in `playwright.config.ts`).
The normal `pnpm dev` uses port 5173; e2e uses 5174 to avoid conflicts.

## Interactive UI Mode

For debugging:

```bash
pnpm test:e2e:ui
```

Opens Playwright's interactive UI with time-travel debugging.
